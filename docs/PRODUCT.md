# 产品方案

> 状态：2026-10-24 与产品对齐定稿（六条决策 + 通知模块）。改行为先改这里再动代码。
> 技术落地见 `docs/ARCHITECTURE.md`，选型见 `docs/STACK.md`。

## 1. 定位

本地优先的求职全流程桌面 Agent。简历资产、岗位情报、投递过程、面试准备全部留在本机
工作区；模型由用户自备（多供应商）；一切有副作用的自动化动作都有人工门控——
在场走界面审批，离场走邮件确认。

## 3. 核心对象

产品的心脏是**主简历**：一份 Markdown 文件，人和 Agent 共同编辑，其余一切都从它派生。

```
resumes/<id>/resume.md   ← 唯一源（用户手编 + Agent 工具改）
  ├─ tailored/<jobId>.md   岗位定制简历（与岗位 1:1；覆盖前快照进 tailored/history/）
  ├─ scripts/<jobId>.md    岗位话术（定稿 sidecar：锁定供引用的版本，旧定稿进 history）
  ├─ reports/              完整性评分报告（可再生成，保留历史）
  └─ history/              每次写入前的快照，可回溯

Company 1──N Job 1──1 Application 1──1 Offer
Job ── 匹配度报告（resume × job，后台任务写入）
Resume ── 通用面试话术；Resume + Job ── 岗位版话术
Resume(+ Job) ── 模拟面试（interviews/<id>.json：轮次记录与总评；问答本体在 interview:<id> 会话）
applications/pipeline.json ── 投递状态流水线（工作区级：有序阶段 + 终态，可自定义「四面」等环节）
```

- **岗位与公司分离**：公司库存调研快照（现金流、上市/融资、规模、来源、抓取时间），
  被 JD 匹配评估与 Offer 对比共用。
- **投递是枢纽**：把「岗位 + 用的哪版定制简历 + 哪套话术 + 状态时间线 + Offer」串起来
  （定制稿与话术都按 jobId 存，投递引用 jobId 即可推导）。
- 主简历需要的结构化字段（如 P4 自动填表）在**使用时由 Agent 从 Markdown 现场提取**，
  不维护第二份结构化数据。

## 4. 交互模型

- 最左侧是模块菜单：简历 / 岗位 / 投递 / 面试 / 公司。点菜单切换右侧内容。
  没有独立「对话」页——所有 LLM 交互都发生在具体模块里。
- **没有会话列表**：每个模块就一条滚动对话，重启自动恢复；对话过长时自动压缩成摘要
  （完整历史保留在本地），跨会话的偏好沉淀在工作区 `memory.md` 里由 Agent 自动加载。
- **模块页内嵌该模块上下文的 Chat**：简历页 = Chat 与 Markdown 编辑器并排；
  一个工作区只有一份主简历（跟随工作区），上传旧简历（PDF / Word / Markdown）
  入口在 Chat 输入框左下角「+」；编辑器实时保存，Agent 通过工具改同一份文件，
  前端监听文件变更实时重渲染。
- 浏览器是内容区的浮层（顶栏地球按钮或 Agent 请求时打开），不再是并列的右栏标签页；
  报告（JD 匹配度 / 简历完整性）走评分卡弹层，审计全文落在 `logs/agent.log`。
- Agent 不是纯聊天：它能自主调用工具编辑 Markdown、读写领域数据、发通知；
  浏览器类副作用动作必须过审批门。

## 5. 通知模块

两类用途，一套服务（SMTP 发送 + IMAP 监控回信）：

1. **纯消息通知**：日报 / 周报 / 岗位推荐发送到指定邮箱，只看不回。
2. **人工确认**：需要人放行的步骤（如自动投递提交前）发确认邮件，10 分钟内回复即放行；
   超时自动再提醒一次；仍未回复视为未放行，Agent 走取消 / 跳过分支。
   任何回信（内容不限）都算放行，回信靠邮件头里的唯一 token 匹配。

整条流程（发送、监控、提醒、超时判定）封装成**独立工具**：模型只能调用工具拿到
`approved / timeout` 结果，接触不到 SMTP 配置与原始邮件通道。

> 落地（2026-10-25）：日报 / 周报在设置里排期（时刻 / 周报选星期），到点由 Agent 汇总
> 当期数据发出，没有记录就如实说；用户在场时的邮件外发走聊天里的界面审批（批准 /
> 拒绝按钮），不在场用确认邮件等回信。SMTP / IMAP 在设置里逐项「测试连接」，密码
> 加密存工作区。真邮箱端到端联调待用户凭据。

## 6. 原则

- 不伪造回复：模型未配置就明确报 `llm_not_configured`，不造示例数据。
- 数据不出本机：除用户配置的模型 API 与 SMTP/IMAP，不向任何第三方外发数据。
- 自动化保守：招聘平台操作默认人在环上；自动投递必须过邮件确认门。
- 模板从简：简历先只有 Markdown；PDF 由开源渲染组件后置接入。
- 不用 embedding：匹配度一律 LLM 直接比对。
