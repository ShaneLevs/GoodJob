# 简历写作详细流程

这份文件是 `resume-writing` 的展开版：用户信息很散、经历段数多、或一次要写完整份简历时，按下面的顺序走。

## 1. 初始化

### 1.1 明确目标

- 目标岗位名称（尽量用招聘平台上的标准叫法）
- 行业与城市
- 公司类型：大厂 / 中小企业 / 初创 / 体制内
- 求职状态：在职找 / 离职找 / 应届 / 转行
- 有没有具体 JD

没有 JD 时不要停下来等：先写通用版，并说明「拿到具体 JD 后可以再做定制稿」。

### 1.2 读已有材料

1. `resume_read` 读主简历现状。
2. `upload_list` 看 upload/ 里有没有旧简历、作品集、证书。
3. 有旧简历时 `upload_read` 读全文，整理成「已有 / 缺失 / 待确认」三列，再向用户确认缺口。
4. 用户以前在对话里说过的经历，优先复用，不重复问。

### 1.3 建立素材表

内部维护一张表，不要直接展示给用户：

| 模块 | 已知 | 缺失 | 待确认 |
| --- | --- | --- | --- |
| 基本信息 | | | |
| 教育背景 | | | |
| 工作经历 | | | |
| 项目经历 | | | |
| 技能证书 | | | |
| 其他 | | | |

## 2. 深度挖掘

### 2.1 提问节奏

- 从最近一段经历开始，往前推。
- 一次 3-5 个问题，等回答再继续。
- 先问事实（时间、公司、职位、职责范围），再问结果（数字、影响），最后问难点（取舍、冲突、失败）。
- 用户回答短时，用「能举个例子吗」「当时还有别的方案吗」「后来结果怎么样」追问。

### 2.2 每段经历的提问清单

**工作经历**

- 公司做什么业务，你所在团队的规模和你的位置。
- 你负责的产品 / 客户 / 区域是什么，覆盖多大范围。
- 日常最重要的三件事是什么。
- 你做过哪件「从没有到有」或「从不好到好」的事。
- 这件事的难点是什么，你做了什么关键决定。
- 结果怎么衡量，有没有数字或前后对比。
- 有没有带人、跨团队推动、对外沟通的部分。

**项目经历**

- 项目为什么做，谁提出来的，目标是什么。
- 你是负责人还是参与者，具体负责哪一块。
- 团队多少人，周期多长，预算 / 资源约束是什么。
- 用了什么技术、方法、流程。
- 上线 / 交付后发生了什么变化。
- 如果重做一次，你会改什么。

**教育与其他**

- 学校、专业、学历、起止时间。
- 与岗位相关的课程、论文、竞赛、社团。
- 证书、语言、作品链接。

### 2.3 成果的分层

按可信度从高到低使用：

1. 精确数字：转化率从 12% 到 18%，成本下降 30 万。
2. 范围数字：服务 200+ 客户，覆盖 5 个省份，团队 8 人。
3. 对比结果：上线后投诉量减半，交付周期从两周缩到三天。
4. 可验证事实：被采纳为部门标准，获年度优秀项目，复用到 3 条业务线。
5. 定性描述：用户反馈变好、返工减少。最后才用，且尽量带场景。

用户提供 1-4 类信息时直接用；只有第 5 类时，提醒用户补一个可验证的指标，补不到就保留定性描述，不编数字。

## 3. 组织初稿

### 3.1 选结构

- 常规：基本信息 → 技能 → 工作 → 项目 → 教育。
- 应届：基本信息 → 教育 → 项目 / 实习 → 技能 → 其他。
- 转行：基本信息 → 个人优势（可迁移能力，3 条以内）→ 项目 → 工作 → 技能 → 教育。
- 技术岗：技能可以放工作经历前；非技术岗通常放后面。

### 3.2 写条目

每条按「动词 + 对象 + 方法 / 规模 + 结果」写。示例：

- 主导客服工单系统重构，把 4 个入口合并成 1 个，平均处理时长从 18 分钟降到 7 分钟。
- 搭建区域经销商培训体系，覆盖 120 家门店，半年内复购率提升 9 个百分点。
- 负责 3 个省份的渠道拓展，新签 46 家客户，年回款约 800 万。

避免：

- 「负责 XX 工作，取得了良好效果」
- 「参与 XX 项目，配合团队完成开发」
- 「熟练使用办公软件」

### 3.3 控制篇幅

- 一页优先。删掉与目标岗位无关的课程、社团、旧经历。
- 同一类成果只留最有代表性的 1-2 条。
- 早期经历可以压成一行：公司 | 职位 | 时间，加一句职责。

## 4. 自检

写入前逐项过：

- [ ] 联系方式完整，求职意向明确。
- [ ] 时间线连续，格式统一。
- [ ] 每段经历至少一条有结果的条目。
- [ ] 没有「负责 / 参与 / 协助」开头的空泛条目。
- [ ] 技能没有夸大，能经得起追问。
- [ ] 与目标岗位无关的内容已删减或合并。
- [ ] 全文没有编造的公司、职位、数字。

## 5. 交接

- 写入后用 2-3 句话说明结构和取舍。
- 列出「需要你确认 / 补充」的清单，按重要性排序。
- 用户要针对某个岗位改写时，转到 `resume-review` 的路径 B。
- 用户要准备面试时，转到 `interview-prep`。
