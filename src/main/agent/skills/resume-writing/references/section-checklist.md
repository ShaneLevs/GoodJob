# 简历各模块清单

写每个模块时对照这份清单。排版按系统提示里的「简历正文格式规则」执行，本文件只管内容和取舍。

## 基本信息

**必须有**：姓名、求职意向、电话、邮箱。
**建议有**：城市、工作年限、作品 / GitHub / 领英（与岗位相关时）。
**不要有**：身份证号、婚育状况、家庭住址、照片以外的个人隐私。

检查：

- 手机号与邮箱能直接联系到你。
- 求职意向和投递的岗位名称一致。
- 链接能打开，不要放需要登录的私密地址。

## 个人优势（可选）

只在经历与岗位有明确差异化时写，3 条以内，每条有事实支撑。

合格：

- 8 年 B 端销售，连续 3 年完成 120% 以上指标，主导过 2 个省份的渠道从 0 搭建。

不合格：

- 学习能力强，认真负责，抗压能力好。
- 热爱互联网，有较强的沟通能力。

## 专业技能

按与岗位的相关度排序，分层写：

- 精通：能独立设计、解决疑难问题、带人。
- 熟练：能独立完成常规工作。
- 了解：用过、知道基本用法。

检查：

- 只写能经得起追问的技能。
- 工具名用招聘方熟悉的写法，不写内部系统代号。
- 正在学的技能单独标注「学习中」，不要混进熟练层。

## 工作经历

每段包含：公司、职位、起止时间、职责范围、成果。

推荐 3-5 条，最近一段最详细：

1. 一条讲职责范围（管什么、多大盘面）。
2. 两到三条讲关键项目 / 动作与结果。
3. 一条讲协作或带人（如有）。

检查：

- 时间倒序，格式统一（如 2021.03 — 2023.08）。
- 每条有明确的个人动作，不把团队成果全写成自己的。
- 结果有数字或可验证事实。
- 早期无关经历已压缩或删除。

## 项目经历

选择与目标岗位最相关的 2-4 个。每个项目写清：

- 项目是什么、为谁解决什么问题。
- 你的角色与负责范围。
- 关键动作与技术 / 方法。
- 结果与规模。

检查：

- 项目不是职责的复述，要有明确起止和目标。
- 个人贡献与团队贡献分开。
- 结果能对上工作经历里的数字。

## 教育背景

必须有：学校、专业、学历、起止时间。

可加：与岗位相关的课程、研究方向、论文、GPA / 排名（优秀时）、奖学金。

检查：

- 应届生可以展开；有多年工作经验时压到 1-2 行。
- 成人教育、专升本、海外学历如实写，不回避。
- 学校名不要缩写到别人看不懂。

## 证书与其他

按相关度排序：岗位硬性要求的证书放最前，其次是语言、竞赛、公开分享、志愿活动。

检查：

- 证书写全称与获得时间，不写「多个证书」。
- 与岗位无关的证书可以不写。
- 兴趣爱好除非与岗位直接相关，否则不写。

## 常见整体问题

| 问题 | 表现 | 处理 |
| --- | --- | --- |
| 只有职责没有结果 | 每段都是「负责…」 | 补结果；补不到就问用户要场景与影响 |
| 关键词缺失 | 与 JD 用词完全对不上 | 用行业通用词重写，不硬塞 |
| 内容太满 | 两页以上、字号很小 | 删旧经历、合并同类项 |
| 内容太空 | 半页、每条一句话 | 展开最近两段经历的细节 |
| 时间线断裂 | 有半年以上空白 | 如实写；有事实就简短说明 |
| 方向不一致 | 简历像在投另一个岗位 | 按目标岗位重排和删减 |
