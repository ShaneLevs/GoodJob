# 面试准备（Interview Prep）

## 适用场景

- 拿到面试通知，要预测问题、组织答案、准备自我介绍与反问。
- 要针对某个岗位写一份面试话术。
- 面试前想检查简历里哪些地方会被追问。

本技能负责「准备」；真正的模拟面试在面试页单独开一场，由那个会话里的面试官提问和给总评。

## 材料从哪来

- 岗位 JD 与匹配度报告：岗位会话用 `job_info`（已锁定当前岗位）；简历会话没有读 JD 的工具，请用户贴 JD，或让他去岗位工作台准备。
- 定制简历：岗位会话用 `job_tailored_read`；简历会话用 `resume_tailored_read`（传 jobId）。
- 主简历：`resume_read`。
- 现有话术：岗位会话用 `job_script_read`；简历会话用 `script_read`（传 jobId）。
- 用户上传的公司资料、JD 文档：`upload_list` → `upload_read`。
- 简历 / 岗位会话没有浏览器工具。需要查公司公开信息时，让用户贴资料，或去公司库 / 岗位库会话里做只读调研，不要假装已经查过。

## 准备流程

### 1. 对齐岗位与简历

先读 JD、定制简历、匹配度报告。列出：

- JD 最看重的 3-5 项能力。
- 简历里最强的 3-5 个证据。
- 两者之间的缺口：缺口就是面试官最可能追问的地方。

匹配度报告里的「待提升项 / 空白项」直接转成高风险问题清单。

### 2. 调研公司与岗位

有材料就从材料里提炼：业务、产品、规模、近期动态、团队结构、面试评价。没有材料就列出需要用户自己查的 5-8 个问题，不要编。

### 3. 预测问题

按四类准备，每类 3-5 题：

| 类型 | 来源 | 例子 |
| --- | --- | --- |
| 专业 / 技术 | JD 核心职责、简历里的技术栈与项目 | 「你这个方案为什么不用 X？」「指标怎么定义的？」 |
| 行为 | 简历里的冲突、失败、跨团队、带人 | 「讲一次你和同事意见不合的经历」 |
| 情境 | 岗位常见难题 | 「上线前一周需求翻倍，你怎么排优先级？」 |
| 动机与稳定性 | 跳槽原因、职业规划、薪资 | 「为什么离开上一家？」「未来三年想做什么？」 |

再加 3-5 个反问。

### 4. 组织答案

每个答案控制在 30-60 秒，按「主张 + 证据 + 结果」或 STAR 组织：

- 开头一句给结论。
- 中间用一件具体的事证明。
- 结尾落到结果或学到的东西。

建立 3-5 个可复用的故事库：一次成功项目、一次失败、一次冲突、一次从 0 到 1、一次带人 / 跨团队。每个故事准备 1 分钟版和 30 秒版。

失败题不要甩锅：背景一句、你的责任一句、怎么补救、后来怎么改。

### 5. 自我介绍

准备两个版本：

- **1 分钟**：现在的身份 + 最相关的两段经历 + 为什么适合这个岗位。
- **3 分钟**：按时间线展开，每段一句结果，最后落到岗位匹配点。

不背逐字稿，记结构和关键词。用户要求逐字稿时再写，并提醒他按自己的语速调整。

### 6. 写进话术文件

- 岗位会话：`job_script_write`（整体覆写，旧版自动快照）；简历会话：`script_write` 按 jobId 写。
- 结构固定：自我介绍 / 项目深挖 / 反问环节。
- 项目深挖用「问题 + 回答要点」的形式，不写长篇大论；每个要点带一个数字或事实。
- 定稿用 `job_script_finalize` / `script_finalize`；定稿后仍可改，改过要重新定稿。

### 7. 模拟面试

建议用户去面试页开一场：轮次按岗位定（3-6 轮），模式按需要选。模拟面试的总评会指出表达、深度、结构、岗位匹配四方面的问题，下一场前据此更新话术。

### 8. 面试后

- 记录被问到的问题、卡壳的地方、面试官追问的方向。
- 把新问题补进话术，更新答案。
- 如果同一类问题反复卡住，回到简历或项目细节里补证据。

## 硬规则

- 不编造经历、项目、数字；答案素材必须来自简历、用户口述或上传材料。
- 不给「标准答案」让用户背；给结构、素材和表达顺序。
- 不承诺押中题；预测只是提高准备覆盖率。
- 薪资只给区间、依据和谈判话术，不替用户定数字。
- 反问环节给能获取信息的问题，不问官网能查到的内容。
