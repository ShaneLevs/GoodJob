# JD 拆解框架

## 一、先确定用哪份 JD

- 用户贴了 JD：以这一份为主，其他样本只做补充。
- 岗位档案里有 JD：用 `job_info` 读全文；JD 为空时先让用户补。
- 用户只给了岗位名：先按岗位通用要求拆，并标注「通用口径」；有具体 JD 后再校准。
- 需要更多样本时，可以让用户再贴 2-3 条同类 JD；不要假装做过平台大数据检索。

有浏览器工具的会话（公司库 / 岗位库）可以打开招聘平台读公开 JD 页面，但只做只读浏览，不登录、不投递、不沟通。

## 二、六大维度

### 2.1 核心岗位职责

提炼「这个岗位每天做什么」：汇总职责描述，合并同类项，按重要性排序，取 Top 5-8。

### 2.2 硬性任职要求

| 维度 | 要看的 |
| --- | --- |
| 学历 | 最低门槛、院校 / 专业偏好 |
| 工作年限 | 最低年限、理想区间 |
| 专业背景 | 是否限专业、是否接受转行 |
| 核心技能 | 必备技能清单、熟练度要求 |
| 工具 | 必须掌握的工具 / 软件 / 平台 |
| 行业经验 | 是否要求同行业、同业务模式 |

### 2.3 软性能力

沟通协作、推动力、学习能力、抗压、结构化思维、执行力、管理经验。只保留 JD 里真有依据的，不要把所有好词都列一遍。

### 2.4 项目经验偏好

- 规模：用户量、金额、团队人数、数据量级。
- 类型：从 0 到 1、从 1 到 100、优化迭代、重构迁移。
- 角色：主导、核心参与、支持。
- 领域：行业、业务场景。
- 成果口径：增长、效率、成本、质量、风险。

### 2.5 证书与资质

专业资格（PMP、CPA、CFA、执业证）、技术认证、行业从业资格、语言成绩、工具认证。区分「必须」与「加分」。

### 2.6 成果导向

业务增长、效率提升、成本下降、质量改善、团队建设、风险合规。判断招聘方最想看哪一类结果。

## 三、三级分类

| 层级 | 判断依据 | 简历策略 |
| --- | --- | --- |
| 🔴 基础必备 | 「必须」「要求」「需具备」，以及年限下限、学历门槛 | 必须在显眼位置有证据，缺了要如实说明 |
| 🟡 进阶加分 | 「优先」「加分」「了解」「熟悉」 | 有就突出，没有不硬凑 |
| 🟢 差异化竞争 | 核心职责里的关键能力、重点项目经验 | 用具体案例和结果展开，决定能否脱颖而出 |

措辞判断：

- 「3 年以上」→ 必备下限。
- 「5 年以上优先」→ 加分项。
- 「熟悉 XX 者优先」→ 加分项，不是必备。
- 职责描述里反复出现的能力 → 差异化竞争项。

## 五、注意事项

- 只有一份 JD 时，结论只代表这一家公司的偏好，不要写成行业规律。
- JD 里含糊的要求（如「有较强的业务理解」）要在诊断里说明你的理解，不要当作硬指标。
- 不同城市的同岗位要求可能不同；用户换城市时重新拆。
- JD 有时效性，分析时标注日期和来源。
