# 简历评分细则

> 这份细则同时用于对话里的诊断，和后台「完整性」评测（`services/tasks.ts` 的 `runIntegrity`）；后台输出整页 HTML 报告。

评分是判断工具，不是精确测量。同一份简历两次评分有 5-10 分浮动是正常的；给用户结论时说清依据，不要只给数字。

## 总分结构（100 分）

| 维度 | 满分 | 权重 |
| --- | --- | --- |
| 基本信息完整性 | 15 | 15% |
| 成果量化程度 | 25 | 25% |
| 专业深度与广度 | 20 | 20% |
| 工作经历质量 | 20 | 20% |
| 教育背景 | 8 | 8% |
| 个人影响力 | 7 | 7% |
| 表达能力 | 5 | 5% |

## 维度 1：基本信息完整性（15）

| 要素 | 分值 | 判断 |
| --- | --- | --- |
| 邮箱 | 2 | 有可用的标准邮箱 |
| 电话 | 2 | 有手机号或可拨通号码 |
| 城市 | 1 | 写清所在地或期望城市 |
| 求职意向 | 2 | 有明确岗位名称 |
| 相关链接 | 3 | GitHub / 作品集 / 领英，按岗位需要 |
| 结构完整 | 5 | 有基本信息、经历、教育、技能等核心章节 |

15 分：联系方式齐全，求职意向明确，结构完整。
10 分左右：只有邮箱和电话，缺链接或求职意向。
5 分以下：信息残缺，招聘方无法联系或判断方向。

## 维度 2：成果量化程度（25）

| 要素 | 分值 | 判断 |
| --- | --- | --- |
| 数字密度 | 8 | 关键条目的比例：大多数条目有数字 / 规模 / 对比 |
| 强动词 | 6 | 主导、搭建、推动、重构等主动动词占多数 |
| 结果占比 | 6 | 描述结果的条目占比，而不是只写职责 |
| 业务影响 | 5 | 能看出对收入、成本、效率、质量的影响 |

扣分：

- 出现「参与」「配合」「协助」「做一些」：按条扣 1-2 分，不整份清零。
- 全是职责描述、没有结果：本维度不超过 10 分。
- 数字明显不可信或自相矛盾：扣 3-5 分并在报告里指出。

25 分示例：

> 主导单体服务迁移，QPS 提升 4.2 倍，P99 从 3.2s 降到 0.8s，每月成本节省约 18 万。

10 分示例：

> 参与了项目开发，负责模型训练，配合团队完成任务。

## 维度 3：专业深度与广度（20）

| 要素 | 分值 | 判断（按岗位方向调整） |
| --- | --- | --- |
| 核心专业能力 | 10 | 技术岗看技术栈与系统复杂度；非技术岗看方法论与案例难度 |
| 前沿 / 高阶能力 | 5 | 技术岗看新框架、性能、架构；非技术岗看策略、体系、规模化 |
| 能力分层 | 3 | 有精通 / 熟练 / 了解，且与经历对得上 |
| 工具链 | 2 | 岗位常用工具能覆盖 |

20 分：技能有层次，经历能证明深度，工具链完整。
12 分左右：技能平铺，能看出会用，但看不出深度。
5 分以下：只列工具名，没有应用场景。

## 维度 4：工作经历质量（20）

| 要素 | 分值 | 判断 |
| --- | --- | --- |
| 公司 / 项目可信度 | 5 | 公司或项目能被理解，职责与平台匹配 |
| 经历完整度 | 4 | 每段有时间、职位、职责、结果 |
| 时间跨度 | 4 | 与岗位要求匹配；转行 / 空窗如实呈现 |
| 职责深度 | 4 | 主导 vs 参与的比例 |
| 成长轨迹 | 3 | 职级、范围、复杂度有递进 |

20 分：经历递进清晰，最近一段有主导性的复杂项目。
10 分左右：经历完整，但以执行为主，缺少独立负责的项目。
5 分以下：经历零散，时间线不清，职责与岗位无关。

## 维度 5：教育背景（8）

| 要素 | 分值 | 判断 |
| --- | --- | --- |
| 学历 | 4 | 博士 / 硕士 / 本科 / 大专，按岗位门槛给 |
| 学校 | 2 | 与岗位要求的匹配度，不唯名校 |
| 成绩 / 论文 | 2 | GPA、排名、论文、研究方向 |

说明：学历不满足硬门槛时单独提醒，不因为学校普通直接给 0；有多年相关经验的候选人，教育权重自然下降。

## 维度 6：个人影响力（7）

按岗位方向选 2-3 项，不要求全有：

- 开源项目、GitHub、作品集（技术 / 设计）。
- 论文、专利、行业分享、公开演讲。
- 专业证书（与岗位相关）。
- 行业社群、媒体、出版的产出。

7 分：有可验证的公开成果。
3-4 分：有证书或零星分享。
0-2 分：没有任何公开产出。非技术岗不因没有 GitHub 扣到 0，可看作品集与行业资源。

## 维度 7：表达能力（5）

| 要素 | 分值 | 判断 |
| --- | --- | --- |
| 结构 | 2 | 章节清楚，条目长度适中，重点靠前 |
| 格式 | 1 | 时间、标点、层级统一 |
| 无套话 | 2 | 没有「认真负责、学习能力强」这类空话 |

扣分：

- 自我评价套话每处扣 1-2 分。
- 全文不足 10 行扣 1 分。
- 排版混乱（时间格式不一、层级跳级）扣 1 分。

## 评分流程

1. 先判岗位方向，选对应的维度口径。
2. 逐维找证据，写下依据（引用原句），再给分。
3. 不机械数关键词：同一个词出现五次不等于能力更强。
4. 计算总分，给出等级：

| 分数 | 等级 | 含义 |
| --- | --- | --- |
| 85-100 | 优秀 | 可以直接投，重点打磨个别条目 |
| 70-84 | 良好 | 改完明显短板再投 |
| 55-69 | 及格 | 需要系统性重写部分模块 |
| 40-54 | 偏弱 | 结构或证据不足，建议重做 |
| 0-39 | 不合格 | 信息残缺或无有效证据 |

5. 报告里必须包含：总分、分项依据、最值得先改的三件事、1-3 条改写示例。

## 行业差异参考（不参与打分）

不同行业的简历门槛不同，但**不要用系数换算总分**：把一份 70 分的行政简历乘 0.45 变成 31.5 分没有实际意义。系数只用于解释「为什么同一个人在不同行业的竞争力感受不同」。

| 行业 | 相对门槛参考 |
| --- | --- |
| AI / 大模型 / 算法 | 1.00（原基准） |
| 金融 / 量化 | 0.92 |
| 自动驾驶 / 机器人 | 0.88 |
| 游戏 / 图形学 | 0.82 |
| 后端 / DevOps | 0.72 |
| 前端 / 移动 | 0.70 |
| 数据分析 | 0.65 |
| 产品经理 | 0.60 |
| 设计 / 建筑 | 0.60-0.65 |
| 财务 / 会计 | 0.55 |
| 教育 / 医疗 | 0.55-0.70 |
| 行政 / 人力 / 销售 | 0.45 |

使用时只写一句「这个行业的简历竞争强度与你原来的行业不同」，不要给「等价分」。
